# kernel-config

`kernel-config.sh` is a pragmatic Bash script for pruning and tuning a Linux kernel `.config` file.

It is designed for people who already build custom kernels and want a repeatable way to:

- remove debug, test, legacy, or unused subsystems
- tune scheduler defaults for server, desktop, or realtime use
- keep only the CPU, GPU, firmware, and platform support they actually need
- enable kernel features commonly required by specific applications
- auto-detect some host characteristics and translate them into kernel config changes

The script edits a temporary copy of an existing kernel configuration using `scripts/config`, runs `make olddefconfig`, and verifies the result. Only then does it create a unique timestamped backup and atomically replace the target config. A failed command or strict validation leaves the original config intact.

It also supports a dry run mode that applies all changes to a temporary copy and prints only the config symbols that would change without modifying the real `.config`.

## What It Does

The script works on an existing kernel source tree and `.config` file.

High-level flow:

1. Resolve paths and validate every option, required tool, and kernel tree prerequisite.
2. Copy the baseline configuration into a private temporary directory.
3. Apply pruning, hardware detection, application profiles, and explicit controls.
4. Run `make olddefconfig`, verify requests, and check initramfs compression against the resulting configuration.
5. If validation permits saving, back up and replace the original configuration.

`--dry-run` performs the configuration work on a temporary copy, prints the final symbol changes, and skips active module probes. It creates no backup and never replaces the original config. Kernel `make` may still build or update configuration tooling in the source/build tree; use `--check` for a read-only prerequisite check that does not run `make`.

It is not a full kernel config generator. It assumes you already have a baseline config and want to refine it.

## Requirements

- Bash 5.2 or later
- a complete Linux kernel source tree, including `Makefile`, `Kconfig`, `scripts/Kconfig.include`, and `kernel/Kconfig.preempt`
- a readable `.config`; saving also requires a writable config and parent directory
- `make`, the kernel's configuration build dependencies, and standard GNU/Linux command-line tools
- an executable `scripts/config`, supplied with the kernel sources
- Python 3.11+ with `lzma` and `bz2` for initramfs inspection, and the accompanying `lib/initramfs_check.py`. Keep the script and `lib/` together when copying them. `--initramfs-generator=none` skips this dependency when no image is supplied.
- `--native-arch` also requires Python 3.11+ and the accompanying `lib/` helpers.

Directories containing only Kconfig snapshots support `--audit-kconfig`, but cannot run configuration changes. Missing source files or a missing/non-executable `scripts/config` produce an error before any configuration changes; `scripts/config` is not generated by `make scripts`.

Relative source paths are resolved from the invocation directory. A relative `CONFIG_FILE`, including `.config`, is resolved within the selected kernel tree. Absolute config paths can point outside that tree.

Some auto-detection features use host tools if available:

- `xfs_info` for XFS feature detection
- `findmnt` for mounted XFS discovery

## Quick Start

```bash
./kernel-config.sh --dry-run /usr/src/linux
./kernel-config.sh /usr/src/linux
make -C /usr/src/linux -j"$(nproc)"
```

You can also point to a specific config file:

```bash
./kernel-config.sh --kernel-srcdir /usr/src/linux --config-file /usr/src/linux/.config
```

Relative config paths are resolved from the kernel source directory, so `.config`
means `<kernel-source>/.config`.

## Usage

```text
./kernel-config.sh [OPTIONS] [KERNEL_SRCDIR] [CONFIG_FILE] [VAR=VALUE...]
```

Supported input styles:

- command-line flags such as `--video-support intel`
- environment variables such as `VIDEO_SUPPORT=intel`
- trailing `VAR=VALUE` assignments
- positional `KERNEL_SRCDIR` and `CONFIG_FILE`

Precedence:

1. Environment variables set defaults.
2. CLI flags override environment variables.
3. Trailing `VAR=VALUE` arguments also override earlier defaults.

Boolean flags are off unless enabled explicitly with `--foo`. For `VAR=VALUE` and `--foo=value`, accepted boolean values are `true/false`, `yes/no`, `on/off`, `enable/disable`, and `1/0`.

`--all-optimizations` is flag-only. Do not pass `ALL_OPTIMIZATIONS=true|false` or `--all-optimizations=<value>`.

`--dry-run` is a boolean flag. When enabled, the script prints only the final `.config` symbols that would change and leaves the real file untouched.

`PROTECTED_CONFIG_SYMBOLS` accepts a comma-separated list of symbols that the script must not modify. Symbols may be passed as `FOO` or `CONFIG_FOO`.

## Main Parameters

### Core tuning

- `DRY_RUN`
  Shows the final `.config` symbol changes without modifying the original config or actively loading/unloading modules.

- `CHECK`
  Validates options, source-tree prerequisites, tools, and config access, then exits without creating files, probing modules, or running `make`. Use `--check --dry-run` to check a read-only baseline. It does not resolve Kconfig dependencies or prove that a kernel build will succeed.

- `STRICT`
  Rejects the result if `olddefconfig` does not preserve requested values, an explicit new control targets a missing symbol, or a protected symbol changes indirectly. Diagnostics identify the symbol and requested/final values. Without this option, discrepancies are reported and the result can still be saved. Later profile operations take precedence over earlier requests for the same symbol; strict mode verifies the final requests.

- `SCHED_CACHE=none|on|off`
  Controls `CONFIG_SCHED_CACHE`, the cache-aware load-balancing option present in the 7.2 reference tree. `none` preserves the current setting. An explicit request on a kernel without this symbol is reported; `--strict` rejects it.

- `KERNEL_COMPRESSION=keep|gzip|bzip2|lzma|xz|lzo|lz4|zstd`
  Selects the kernel image compression format. Default: `keep`. Availability depends on the target architecture and Kconfig dependencies.

- `INITRD_COMPRESSION=keep|auto|none|gzip|bzip2|lzma|xz|lzo|lz4|zstd`
  Enables initrd support and the selected decompressor, retaining all existing decompressors. `auto` adds the decoders required by the detected producer and supplied image; `none` enables uncompressed initramfs support without removing decoders. Default: `keep`. This does not repack an initramfs or set its producer's compression format. A non-`keep` value conflicts with `INITRD_SUPPORT=off`.

- `INITRAMFS_GENERATOR=auto|genkernel|ugrd|none`
  Read-only compression compatibility inspection. Default: `auto`. An explicit selection wins; automatic detection reads `/etc/kernel/install.conf` (or the vendor `/usr/lib/kernel/install.conf` when absent), then falls back to the only installed supported builder. Merely finding `/etc/genkernel.conf` does not select genkernel. Ambiguous/missing/unsupported builders are reported as **unknown**, not compatible. For offline/cross builds use explicit target evidence, or select `none` to skip producer inspection. A supplied image is still checked with `none`.

- `INITRAMFS_CONFIG=PATH` / `--initramfs-config PATH`
  Optional producer configuration. Otherwise uses `/etc/genkernel.conf` or `/etc/ugrd/config.toml`. Paths are relative to the invocation directory, unlike the kernel `.config` argument. TOML is parsed as data; shell configuration accepts literal assignments and the standard `GK_SHARE` default expression only. Dynamic expressions and sourced files are reported as unknown and never executed.

- `INITRAMFS_COMPRESSION=auto|none|best|fastest|gzip|bzip2|lzma|xz|lzo|lz4|zstd`
  Describes a compression override you will pass to the producer's command line. Default `auto` reads producer settings/defaults. It does **not** edit those settings or invoke the builder. This is distinct from `--initrd-compression`, which configures kernel decoders.

- `INITRAMFS_IMAGE=PATH` / `--initramfs-image PATH`
  Optional existing raw initramfs to inspect. Reads stream headers and CPIO lengths, including early uncompressed microcode, padding, and concatenated archives. Both the producer's future format and the supplied image's formats must be supported. Images are not selected by filename or guessed from the newest file in `/boot`.

The report separates **kernel image**, **initramfs**, **module**, and **firmware** compression. These do not need to use the same format: `KERNEL_ZSTD=y` and an XZ initramfs are compatible when `BLK_DEV_INITRD=y` and `RD_XZ=y`. Modules/firmware lines report Kconfig selections; they do not certify every installed module or firmware file.

The genkernel adapter reads its installed compression table and checks executable availability, including the `lzop`/`LZO` mapping and command flags for XZ and legacy LZ4. `best`/`fastest` remain dynamic: the report lists eligible installed compressors with `RD_*=y` in the final configuration, without claiming which one genkernel will choose. If there are no eligible decoders, select a format explicitly. Integrated initramfs builds require separate `INITRAMFS_SOURCE`/`INITRAMFS_COMPRESSION_*` review and are reported as unknown.

The ugrd adapter supports the verified 2.x XZ/ZSTD/uncompressed interface. It checks defaults and Python compression dependencies in the builder's interpreter (including an unambiguous Gentoo python-exec launcher). Having the `zstd` executable does not substitute for Python `zstandard`. Unknown versions, custom build hooks, or ambiguous interpreters are not certified. Neither adapter runs genkernel/ugrd or changes their configuration.

**Root coverage.** The inspection also reads `/proc/self/mountinfo` and sysfs (never `blkid`, `mdadm` or `lvm`) to learn which layers sit under `/`: md arrays (`md/level`, `md/metadata_version`, `md/uuid`), LVM and LUKS device-mapper targets (`dm/uuid` prefix), partitions and nested `slaves/`. The inspected host is `--host-root` of the discover phase (`HOST_ROOT`, default `/`), so a chroot can be checked. With ugrd, each layer needs its module in the image: `ugrd.fs.mdraid` for md, `ugrd.fs.lvm` for LVM, `ugrd.crypto.cryptsetup` for LUKS. When the root is a device-mapper node (LVM or LUKS, possibly on md), ugrd 2.x's `_autodetect_dm` follows the slaves recursively and enables every one of them, so an unlisted module is reported as `autodetected` with a **warning** that recommends listing it. That autodetection is off when `hostonly`, `autodetect_dm` or the layer's switch (`autodetect_lvm`, `autodetect_raid`, `autodetect_luks`) is `false`, and it does not cover a root mounted directly from `/dev/mdN`: there it stops at «No device mapper name found» and never reaches the `linux_raid_member` check, so a host with root on `/dev/md127` (RAID5, metadata 0.90) got an initramfs without `mdadm`. In those cases an unlisted module is **incompatible**. When other md arrays exist, `ugrd.fs.mdraid` copies the host `/etc/mdadm.conf` and runs `mdadm --assemble --scan`; if that file has no `ARRAY` entry for the root array's UUID (and no `[copies.*]` entry replaces `/etc/mdadm.conf`), assembly depends on scanning every member at boot, so the report emits a **warning** (a slow USB member can leave another array half assembled). The final `.config` must provide the layer symbols as `y` or `m`: `BLK_DEV_MD` plus the level symbol (`MD_RAID0`, `MD_RAID1`, `MD_RAID10`, `MD_RAID456`, `MD_LINEAR`) for md, `BLK_DEV_DM` for LVM, `BLK_DEV_DM` and `DM_CRYPT` for LUKS. With genkernel the root device is reported as a note only (its `--mdadm`/`--lvm`/`--luks` options are not inspected). Roots that are not a single block device (btrfs multi-device, zfs, nfs, `rootfs`) and `/dev/root` are reported as notes, not failures. Warnings are shown but never fail validation or `--strict`.

```
Initramfs compression: incompatible
  Generator: ugrd 2.2.0 (only installed supported generator (inferred))
  Producer format: xz
  Root device: /dev/md127 (md raid5, metadata 0.90)
    ugrd.fs.mdraid: missing
    Other md arrays: md1, md2 (mdadm.conf: not covered)
  ...
  incompatible: ugrd root coverage: ugrd.fs.mdraid is not listed in modules of /etc/ugrd/config.toml; ...
  warning: other md arrays present (md1, md2); /etc/mdadm.conf (copied by ugrd.fs.mdraid) has no ARRAY entry for the root array, ...
```

Stacked layers are joined with ` on `, for example `Root device: /dev/mapper/vg-root (lvm vg-root on crypt cryptroot on md raid1, metadata 1.2)`.

Known ugrd 2.x behaviour the report cannot predict: the build aborts in `get_virtual_block_info` when sysfs exposes an inactive md device without `md/uuid` (an empty `/dev/md0` left by autodetection). When the root filesystem is on a plain partition, `masks.build_enum = "get_virtual_block_info"` in `/etc/ugrd/config.toml` skips that detection (the key is `masks`; the sample file says `mask`). On Gentoo, `sys-kernel/installkernel` with `USE=systemd` delegates to systemd's `kernel-install`, which fails on old running kernels with "Protocol driver not attached"; `SYSTEMD_KERNEL_INSTALL=0 make install` uses the shell implementation with the same `install.d` hooks.

Image inspection supports uncompressed newc/crc CPIO and gzip, bzip2, XZ, LZMA-alone (usual `0x5d` properties), ZSTD, legacy LZ4, and the kernel's lzop/LZO framing. XZ requires CRC32 or no check; CRC64/SHA256 are rejected. ZSTD/LZ4/LZO inspection checks framing, not payload integrity/checksums. UKI/U-Boot wrappers and unrecognized formats are reported as unknown; modern LZ4 framing is rejected. Inspection is bounded to 128 MiB compressed input, 256 MiB expanded data, and 256 archive members. These checks concern compression compatibility, not a boot/signature certification.

`--strict` rejects incompatible **or unknown** evidence after `olddefconfig`, before committing the configuration; **warning** findings (such as the root-coverage `mdadm.conf` notice) are printed but never fail, with or without `--strict`. Without strict mode the report warns and other changes may still be saved. `--check --strict` validates the existing configuration without running make; it does not simulate decoder additions requested by `auto`. No generators, images, `/boot` files, or running modules are changed by these checks. Existing decoders are preserved unless explicitly disabled, and final validation catches removal of a required decoder.

References: [kernel initramfs format](https://www.kernel.org/doc/html/latest/driver-api/early-userspace/buffer-format.html), [kernel XZ restrictions](https://docs.kernel.org/staging/xz.html), [genkernel compression handling](https://github.com/gentoo/genkernel/blob/master/gen_configkernel.sh), [ugrd CPIO writer](https://github.com/desultory/ugrd/blob/main/src/ugrd/fs/cpio.py).

```bash
# Inspect the current config/image without running make or a builder.
./kernel-config.sh --check --strict --initramfs-generator=ugrd \
  --initramfs-image=/boot/initramfs-7.2.0-gentoo.img /usr/src/linux

# Preview additions required by the installed generator and existing image.
./kernel-config.sh --dry-run --strict --initrd-compression=auto \
  --initramfs-image=/boot/initramfs-7.2.0-gentoo.img /usr/src/linux

# Model an explicit future ugrd --compress zstd invocation, without running it.
./kernel-config.sh --dry-run --strict --initramfs-generator=ugrd \
  --initramfs-compression=zstd --initrd-compression=auto /usr/src/linux
```

- `FIRMWARE_COMPRESSION=keep|on|off`
  Preserves firmware decoding by default (the `server` profile adds the XZ and ZSTD decoders). `on` requests compressed firmware support with XZ and ZSTD; `off` explicitly disables compressed firmware support.

- `ALL_OPTIMIZATIONS`
  Enables the script's optimization preset: `OPTIMIZATION_PROFILE=server`, kernel `ZSTD` compression and server profile zswap tuning (`zstd`, falling back to `lz4`; the initial compression preset uses LZO). It preserves existing initramfs and firmware decompression support and does not disable shared compression libraries.
  It also turns on every pruning toggle except `PRUNE_HARDENING` and `PRUNE_UNUSED_MODULES`: observability, legacy, debug/trace, selftests, sanitizers, coverage, fault injection, dangerous options, BPF, 32-bit compatibility, unused network protocols, old hardware, old x86 platforms, legacy ATA, insecure protocols, radios and DMA attack surface. Unless an application profile restores them (such as trace events for `rasdaemon`, and debugfs when its rasdaemon release or CPU needs it), the result has no debugfs, ftrace, kprobes or BTF (bpftrace and `perf probe` stop working), no `IA32_EMULATION`, and on 6.17+ no iptables-legacy tables unless `iptables-legacy` or `firehol` is among the applications. A toggle can be turned off again after the flag, for example `--prune-compat32=false`.
  This setting is flag-only and must be enabled with `--all-optimizations`. To keep the existing kernel image compression, pass `--kernel-compression=keep` after this flag.

- `OPTIMIZATION_PROFILE=none|server|desktop|realtime`
  Adjusts scheduler, preemption, and HZ defaults. Desktop and server select THP `madvise` rather than applying hugepages to every eligible mapping; desktop also requests full preemption with dynamic switching. Server prefers non-preemptible operation where that model's dependencies are met, then lazy, voluntary, or full preemption. Realtime requests RT only when its prerequisites are already enabled; otherwise it reports the fallback. Each profile selects a single tick mode. Explicit controls below override profile defaults.

  Server/desktop NUMA balancing is requested only when NUMA is already enabled or explicitly requested, using the kernel version's migration dependencies. Explicit `--numa-balancing=off` suppresses this default.

  Current profile behavior:

  All profiles enable `CC_OPTIMIZE_FOR_PERFORMANCE`, topology-aware scheduling (`SCHED_MC`, `SCHED_SMT`, `SCHED_CLUSTER`, `SCHED_MC_PRIO`), the TEO cpuidle governor (`CPU_IDLE_GOV_TEO`), `RSEQ`, and disable `SLUB_TINY`, `BASE_SMALL` (when `EXPERT=y` exposes it), and the Project C alternative scheduler (`SCHED_ALT`, BMQ/PDS from gentoo-sources `USE=experimental`, which replaces EEVDF and rules out PSI, `SCHED_CACHE`, `SCHED_CORE`, NUMA balancing, `UCLAMP_TASK`, `PREEMPT_RT` and sched_ext). On 6.12–6.18 kernels where `SLUB_CPU_PARTIAL` still exists (before slab sheaves replaced per-CPU partial slabs), `server` and `desktop` keep per-CPU partial caches enabled when `SMP=y`, while `realtime` disables them as recommended by `mm/Kconfig` to avoid overflow lock latency spikes. On x86_64 they replace the frame-pointer unwinder with ORC (`UNWINDER_ORC`). `arch/x86/Kconfig.debug` documents that unwinder as 5-10% faster than frame pointers, at roughly 2-4MB more RAM, and it is the x86_64 default. A baseline already using `UNWINDER_GUESS`, a protected choice member, or an explicit `--enable-symbols`/`--disable-symbols` for the choice is left alone. arm64 selects `FRAME_POINTER` itself and has no ORC unwinder, so it is unchanged. They also enable `CRC_OPTIMIZATIONS` when that symbol exists (6.18+; `lib/crc/Kconfig` says to keep it enabled unless minimizing size, because disabling it makes CRC much slower) and `RAID6_PQ_BENCHMARK` whenever `RAID6_PQ` is enabled (`y` or `m`), so RAID6 automatically picks the fastest SIMD implementation at init. On 6.12, which has no such symbol, a slower `CRC32` implementation (`CRC32_SLICEBY4`, `CRC32_SARWATE` or `CRC32_BIT`) is moved to `CRC32_SLICEBY8` when `CRC32` is enabled. That is the choice default, and `lib/Kconfig` calls it the fastest of the four. When the baseline already has `BPF` and a JIT backend (`HAVE_CBPF_JIT` or `HAVE_EBPF_JIT`), all profiles also enable `BPF_JIT` so seccomp-bpf, socket filters and eBPF execute as native machine code instead of in the software interpreter, and enable `BPF_JIT_ALWAYS_ON` when `BPF_SYSCALL` and `HAVE_EBPF_JIT` are present (matching Fedora, RHEL, Arch, Ubuntu and Gentoo dist-kernel; pass `--disable-symbols=BPF_JIT_ALWAYS_ON` to keep the interpreter fallback). When `NET` is enabled, all profiles also restore the upstream SMP network-scaling defaults (`PCPU_DEV_REFCNT`, `BQL`, `RPS` and `RFS_ACCEL`) whenever their `SMP`/`SYSFS` dependencies are met. On x86_64, all optimization profiles and guest host types also enable `X86_X2APIC` when its prerequisites (`X86_LOCAL_APIC` plus either `IRQ_REMAP` with `IOMMU_SUPPORT` or `HYPERVISOR_GUEST`) hold: it replaces MMIO local-APIC accesses (and VM-exiting MMIO traps in guests) with faster MSR accesses and falls back safely on hardware without x2APIC.

  Hardware-specific AES-NI and posted MSI tuning requires `--native-cpu=auto`
  or `--native-cpu=on` and positive local hardware evidence, described below.
  Optimization profiles alone leave these options unchanged.

  - `server`
    Prioritizes throughput and stable background behavior:
    Preemption preference is `PREEMPT_NONE`, then `PREEMPT_LAZY`, `PREEMPT_VOLUNTARY`, or full preemption, skipping a model whose direct dependencies are unmet. From Linux 7.4 (`7dadeaa6`, "sched: Further restrict the preemption modes") `PREEMPT_NONE` depends on `ARCH_NO_PREEMPT` and `PREEMPT_VOLUNTARY` depends on `!ARCH_HAS_PREEMPT_LAZY`. x86, arm64 and the other lazy-preemption architectures therefore get `PREEMPT_LAZY`, the model upstream left in place of the old server and voluntary choices. A config migrated from 6.18 still lists `PREEMPT_NONE`; the profile does not request it once the dependency is unmet, because strict mode would reject the run. It requests `NO_HZ_IDLE` and a low timer rate preference (`HZ_100`, then `HZ_250`, `HZ_300`, `HZ_1000`). `NO_HZ_FULL` is left to the realtime profile and to `--tick-mode=full`: `Documentation/timers/no_hz.rst` says adaptive ticks should not be enabled by default, and selecting it removes `TICK_CPU_ACCOUNTING` (`VIRT_CPU_ACCOUNTING_GEN`, which it forces, is documented as a significant cost and "only useful if you are working on the full dynticks subsystem"). The `HAVE_CONTEXT_TRACKING_USER` and `HAVE_VIRT_CPU_ACCOUNTING_GEN` symbols are architecture capabilities, enabled on every 64-bit x86 build, so they are not evidence that the baseline wanted full dynticks.
    It also enables `SCHED_CACHE` and Multi-Gen LRU when those symbols are available.
    Memory: zswap on with the `zstd` default compressor (falls back to `lz4`), `ZSWAP_SHRINKER_DEFAULT_ON`, `PERSISTENT_HUGE_ZERO_FOLIO`, and `RSEQ_SLICE_EXTENSION` when present.
    CPU time accounting switches to `TICK_CPU_ACCOUNTING` unless the selected tick mode uses `NO_HZ_FULL`.
    It makes `mq-deadline`, `kyber`, BBR (`TCP_CONG_BBR`), `NET_SCH_FQ` and `NET_SCH_FQ_CODEL` available without changing the `DEFAULT_*` choices; symbols already built as modules stay `=m`.
    It enables compressed firmware loading (`FW_LOADER_COMPRESS` with XZ and ZSTD) when the kernel has a firmware loader: `linux-firmware` built with `compress-zstd` or `compress-xz` installs `.zst`/`.xz` files, and without the decoders a driver such as `ice` cannot load them (the E810 then runs in safe mode). `--firmware-compression=off` overrides it.
    It keeps soft-lockup and hung-task detection (`SOFTLOCKUP_DETECTOR`, `DETECT_HUNG_TASK` with its blocker dump), the main evidence of a storage, NFS or Ceph hang, even after `--prune-debug-trace`. Kconfig gates them behind `DEBUG_KERNEL`; when the profile turns that on it keeps off what `DEBUG_KERNEL` would add by default (`DEBUG_MISC`, `X86_DEBUG_FPU`, `RCU_TRACE`) and keeps `DEBUG_INFO_NONE`, while a baseline that already had `DEBUG_KERNEL` keeps its own choices. The hard-lockup detector, which takes a PMU counter per CPU, is left alone.
    It disables `NO_PAGE_MAPCOUNT`, still marked EXPERIMENTAL in 7.2, and `RT_GROUP_SCHED` (default `n`): with it, `SCHED_FIFO`/`SCHED_RR` tasks outside the root cgroup fail until each group is given an RT budget, which breaks systemd services and containers that request real-time priority. A host that budgets RT time per cgroup (`docker run --cpu-rt-runtime`) passes `--enable-symbols=RT_GROUP_SCHED`.
    Memory error recovery: `MEMORY_FAILURE` (and `ACPI_APEI_MEMORY_FAILURE` with APEI), so an uncorrectable error in a user page, such as a VM's RAM, kills its owner instead of panicking the host; `RAS_CEC` also soft-offlines pages with repeated corrected errors when `DEBUG_FS` is enabled, which Kconfig requires (`--all-optimizations` prunes it; rasdaemon can do that offlining instead).
    THP defaults to `madvise`: QEMU marks guest RAM with `MADV_HUGEPAGE`, so virtual machines keep huge pages, while databases that ask for THP off are not forced into them.
    It disables `RCU_NOCB_CPU_DEFAULT_ALL`. Offloading callbacks on every CPU adds a kthread per CPU and increases `call_rcu()` overhead and context-switch rates (`kernel/rcu/Kconfig` says to leave it off when unsure). Fedora and RHEL build `RCU_NOCB_CPU` but leave this option off, so `rcu_nocbs=` and `nohz_full=` still choose the CPUs. The profile does not request `RCU_NOCB_CPU`: it depends on `RCU_EXPERT` or `NO_HZ_FULL`, and `NO_HZ_FULL` selects it. An existing `RCU_EXPERT` baseline keeps its own value. `profiles/server-kvm-host.sh` still disables `RCU_NOCB_CPU_DEFAULT_ALL` explicitly so a baseline from an older run, which enabled it, converges even when a trailing `--disable-symbols` replaces that list.

  - `desktop`
    Prioritizes interactivity:
    full preemption when supported, `PREEMPT_DYNAMIC` when supported, `NO_HZ_IDLE`, `SCHED_AUTOGROUP`, and a high timer rate preference (`HZ_1000`, then `HZ_300`, `HZ_250`, `HZ_100`).
    For THP defaults, it selects `TRANSPARENT_HUGEPAGE_MADVISE` when available.
    It also enables `SCHED_CACHE` and Multi-Gen LRU when supported.
    It enables `UCLAMP_TASK_GROUP` when the CPU controller and per-task uclamp
    are available, exposing `cpu.uclamp.min`/`cpu.uclamp.max` for cgroup performance
    hints. This also applies to explicit `--uclamp=on` with existing CPU cgroups.
    Like [CachyOS](https://github.com/CachyOS/linux-cachyos/blob/master/linux-cachyos/config)
    and [Qubes' Fedora-based configuration](https://github.com/QubesOS/qubes-linux-kernel/blob/main/config-base),
    it builds the capability; applications or service policies must supply the
    hints. See [utilization clamping](https://docs.kernel.org/scheduler/sched-util-clamp.html).
    `--uclamp=off`, disabled dependencies, protected values and
    `--disable-symbols=UCLAMP_TASK_GROUP` take precedence.
    Memory: zswap on with the `lz4` default compressor (falls back to `zstd`), `ZSWAP_SHRINKER_DEFAULT_ON`, `PERSISTENT_HUGE_ZERO_FOLIO`, `RSEQ_SLICE_EXTENSION`, and `TICK_CPU_ACCOUNTING` (same rule as `server`).
    It makes BFQ (`IOSCHED_BFQ`, `BFQ_GROUP_IOSCHED`) and `mq-deadline` available,
    enabling `BLK_CGROUP` so BFQ can distribute I/O bandwidth by cgroup weight.
    All optimization profiles enable `CGROUPS` for their CPU/IO controllers,
    including when the baseline has cgroups disabled. Existing modular I/O
    schedulers stay modular; selecting the active scheduler remains a runtime
    choice. See [BFQ group scheduling](https://docs.kernel.org/block/bfq-iosched.html#group-scheduling-with-bfq)
    and [Red Hat's scheduler guidance](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/10/html/monitoring_and_managing_system_status_and_performance/setting-the-disk-scheduler).

  - `realtime`
    Prioritizes deterministic low-latency execution:
    `PREEMPT_RT` when its prerequisites are enabled (otherwise full preemption), `HZ_1000` preference, `RCU_BOOST`, and `RCU_NOCB_CPU` support. It requests `NO_HZ_FULL` when the baseline enables SMP and the accounting capabilities full dynticks requires, otherwise `NO_HZ_IDLE`. `RCU_NOCB_CPU_DEFAULT_ALL` is left unchanged.
    RCU boosting and callback offloading are requested only when their
    dependencies hold after preemption/tick overrides. In particular, the
    full-preemption fallback without `RCU_EXPERT` omits `RCU_BOOST` and
    `RCU_NOCB_CPU_CB_BOOST`; idle/periodic ticks without `RCU_EXPERT` also omit
    `RCU_NOCB_CPU`. The profile preserves `EXPERT`/`RCU_EXPERT` and respects
    protected or explicitly disabled RCU options.
    Full dynticks isolation also requires boot configuration (for example `nohz_full=` and CPU isolation/affinity tuning).

  The `server`/`desktop` profiles and the compression preset enable `SWAP`
  before configuring zswap, so its compressor and shrinker survive
  `olddefconfig` even when the baseline has swap support disabled.
  Kconfig selects the allocator's required build level, allowing a modular
  `ZSMALLOC` used by zram to become built-in when zswap needs it.
  `--zswap=off` disables the compressed cache; swap support remains available.
  This builds kernel support only: [zswap needs an active backing swap device](https://docs.kernel.org/admin-guide/mm/zswap.html)
  to reduce swap I/O, and the script does not create or activate one.

- `VALIDATION_MODE=warn|strict`
  Checks every config value requested by the script after `make olddefconfig`.
  `warn` (the default) reports values changed by Kconfig dependencies and continues.
  `strict` enables the same transactional validation as `--strict`: an unavailable or overridden request exits non-zero without replacing the original config.

- `PREEMPT_MODE=auto|none|voluntary|lazy|full|rt`
  Overrides the preemption choice made by `OPTIMIZATION_PROFILE`. `auto` keeps profile behavior.
  An explicit unavailable mode is reported by final validation.

- `TIMER_HZ=auto|100|250|300|1000`
  Overrides the profile's timer frequency. `auto` keeps its ordered fallback behavior;
  an explicit value requires that exact `HZ_*` choice (or a direct `CONFIG_HZ` integer).

- `SCHED_CACHE_MODE=auto|on|off`
  Controls cache-aware scheduler load balancing introduced by newer kernels.
  `auto` enables it for `server` and `desktop` when available and otherwise preserves the baseline.

- `MGLRU_MODE=auto|on|off`
  Controls `CONFIG_LRU_GEN` and `CONFIG_LRU_GEN_ENABLED`.
  `auto` enables Multi-Gen LRU for `server` and `desktop`. Historical debug statistics remain disabled.

- `NUMA_BALANCING_MODE=auto|on|off`
  Controls automatic NUMA memory/task placement independently of `NUMA_SUPPORT`.
  On Linux 7.2 and newer, enabling it also enables `CONFIG_NUMA_MIGRATION`; on older trees it enables the generic migration dependency when present.

- `NATIVE_CPU=none|auto|on|off`
  Opts into local hardware tuning, independently of the optimization profile:

  | Mode | Hardware acceleration | Native compilation |
  | --- | --- | --- |
  | `none` (default) | Preserve baseline | Preserve baseline |
  | `auto` | Enable supported options after detection | Preserve `X86_NATIVE_CPU` |
  | `on` | Same detection as `auto` | Enable `X86_NATIVE_CPU` (`-march=native`, x86_64, Linux 6.16+) |
  | `off` | Preserve baseline | Disable `X86_NATIVE_CPU` |

  `auto` also works on older trees without `X86_NATIVE_CPU`. `on` still requires
  the Kconfig symbol and compiler support; strict validation rejects an unmet
  request. Build an `on` configuration on the CPU model that will run the kernel.
  With `CROSS_COMPILE` set, `auto` skips local hardware detection and `on` reports
  an invalid native-compilation request. Run detection on the intended machine,
  or supply a captured host tree through `KC_HOST_ROOT` for offline analysis.

  - **AES-NI/VAES and x86 crypto acceleration:** `CRYPTO_AES_NI_INTEL` is made available only when `aes`
    appears in every visible processor's `/proc/cpuinfo` flags and AES/crypto
    are enabled in the target config (including by `--applications=cryptsetup`).
    Missing or incomplete CPU information skips the request. This works on
    Intel and AMD x86 CPUs; the driver chooses its AES-NI/VAES implementation
    at runtime. Existing built-ins stay built-in; otherwise it is a module when
    supported. `KMSAN` builds are excluded. On kernels with `CRYPTO_LIB_AES_XTS`,
    libaes already provides the accelerated bulk modes and needs no extra
    driver request. On 6.12–6.18 trees where arch-specific crypto modules still
    exist, `pclmulqdq`, `ssse3` and `sse4_2` similarly enable
    `CRYPTO_GHASH_CLMUL_NI_INTEL`, `CRYPTO_POLYVAL_CLMUL_NI`,
    `CRYPTO_SHA1_SSSE3`, `CRYPTO_SHA256_SSSE3`, `CRYPTO_SHA512_SSSE3`,
    `CRYPTO_CRC32C_INTEL` and `CRYPTO_CRCT10DIF_PCLMUL` only when the
    corresponding base algorithm is already enabled. See the [upstream migration notes](https://github.com/torvalds/linux/blob/master/arch/x86/crypto/Kconfig).
  - **CPU facilities:** `x2apic` enables `X86_X2APIC` when the APIC/remapping or
    guest dependencies hold; `fred` enables `X86_FRED`; `mce` together with `mca`
    enables machine-check handling and the detected Intel/AMD MCE extension; and
    (unless `PRUNE_HARDENING` is active) `umip`, `pku` and `user_shstk` enable
    `X86_UMIP` (when visible), `X86_INTEL_MEMORY_PROTECTION_KEYS` and
    `X86_USER_SHADOW_STACK`.
    Each CPU flag must be present on every visible processor. In native mode,
    generic optimization/guest profiles defer x2APIC selection to this check.
    Active `scaling_driver` entries under CPUFreq select `X86_INTEL_PSTATE`,
    `X86_AMD_PSTATE` or `X86_ACPI_CPUFREQ` (deduplicated across CPU policies);
    an active `intel_idle` or `haltpoll` cpuidle driver selects `INTEL_IDLE` or
    `HALTPOLL_CPUIDLE`. Their CPUFreq/idle parents are restored when permitted.
    Vendor identity alone is not proof that firmware exposes HWP/CPPC or usable
    idle tables. Hidden architecture capabilities remain under Kconfig control.
  - **Posted MSI:** `X86_POSTED_MSI` requires x86_64, enabled Intel IOMMU and
    interrupt-remapping dependencies, `cx16` on every visible CPU, and readable
    `intel-iommu/cap` and `ecap` registers for every unit in `/sys/class/iommu`.
    Each unit must advertise interrupt posting (CAP bit 59) and remapping
    (ECAP bit 3), following the [kernel's capability checks](https://github.com/torvalds/linux/blob/master/drivers/iommu/intel/irq_remapping.c).
    A DMAR table alone is insufficient. Missing, malformed or unsupported
    capabilities skip the request, as do known disabling boot options such as
    `nointremap`, `intremap=off,nopost`, `intel_iommu=off`, `iommu=off,soft` or
    `pci=nomsi`. Runtime use still requires the
    [`intremap=posted_msi` boot parameter](https://docs.kernel.org/admin-guide/kernel-parameters.html)
    and successful driver initialization; the script does not edit boot parameters.

  Detection reads `/proc` and `/sys` and prints the evidence or the reason for
  skipping each option. It does not disable baseline drivers when hardware is
  absent or information is unavailable. Explicit symbol overrides and protected
  values take precedence. Missing CPU flags are treated as unconfirmed support,
  not proof of absent hardware; see [x86 CPU flags](https://docs.kernel.org/arch/x86/cpuinfo.html).

  ```bash
  ./kernel-config.sh --dry-run --strict --optimization-profile=server --native-cpu=auto /usr/src/linux
  ```

- `NATIVE_ARCH=true|false` / `--native-arch` / `--nativer-arch`

  Adds support for detected local hardware. Both flag spellings are equivalent;
  the default is `false`. It defaults `NATIVE_CPU` to `auto` and
  `PLATFORM_DRIVERS` to `auto`, and reuses the platform-driver collectors and
  initrd, NUMA, DMA, UEFI, TPM and IOMMU detectors. Only positive evidence adds
  candidates. With platform detection enabled, confirmed non-ECC system memory
  also removes the platform's DRAM ECC drivers and `RAS_CEC`; missing or conflicting
  evidence preserves existing support. Their explicit CLI/environment controls, including `none`, take precedence
  regardless of argument order. Native compilation remains separately opt-in
  through `--native-cpu=on`.

  Discovery reads all available sysfs buses/classes, block devices and
  `/proc/self/mountinfo`. It uses each device's bound module or its modalias
  (including MDIO `phy_id` aliases) and the running kernel's installed module
  metadata, then reuses the target tree's Kbuild module-to-symbol map (joining
  line continuations, relative object paths and single-module subdirectory
  delegations). This covers PCI/PCIe port
  services/USB, SATA/NVMe/SCSI, SD/MMC, USB4/Thunderbolt, network/MDIO PHYs and
  wireless devices, TPM transports, graphics, sound, input, sensors (including
  active `drivetemp`/`nvme` hwmon, `powercap` RAPL domains, standard active
  ACPI AC/battery/button/fan/thermal devices, and unbound I2C DDR4/DDR5
  `spd5118`/`jc42`/`ee1004` devices) and other registered drivers. Disabled ACPI devices
  (`status=0`) and ACPI companion nodes whose `physical_node` is already bound
  are skipped; multicast `input:` handlers (`evdev`, `input_leds`) and
  `hid_generic` fallbacks are resolved without false ambiguity.
  Known standard controller and interface classes also identify NVMe, USB host
  controllers, USB4, SDHCI, HD Audio, FireWire OHCI, USB audio/UVC video/CDC
  ACM/CDC Ethernet/Bluetooth HCI without a loaded driver. PCI AHCI additionally
  requires a block, SCSI or identified ATA device below that controller in
  sysfs; an empty controller's bound driver or modalias alone does not add SATA
  support. Unmounted disks, optical drives without media and devices awaiting a
  block driver count as attached. An unbound controller or incomplete sysfs
  cannot prove that its ports are empty: the script reports the missing
  evidence, keeps baseline settings and honors `--enable-symbols=SATA_AHCI` for
  hotplug or recovery. To remove previously enabled AHCI after verifying it is
  unused, pass `--disable-symbols=SATA_AHCI`; Kconfig derives `SATA_HOST` from
  the remaining drivers. Active SCSI disks/optical/tape drives, USB storage/UAS,
  md RAID levels, dm layers (LVM thin/cache/snapshot/RAID/writecache/VDO,
  multipath, LUKS, dm-integrity), and mounted local/network filesystems (with
  VFAT NLS codepages/iocharsets) add their required support.
  `PCI_MSI` requires allocated interrupts in a detected PCI device's
  `msi_irqs`; posted MSI has the stronger `NATIVE_CPU` checks above.

  Candidates and their subsystem/vendor menus are checked with `olddefconfig`
  on a separate temporary config before becoming requests. Unresolved aliases,
  ambiguous/missing Kbuild mappings and unavailable dependencies are reported
  for manual review. Hidden symbols are left to Kconfig. Explicit symbol
  settings and protected values take precedence; detected drivers can restore
  support removed by a pruning preset. Accepted built-ins/modules retain their
  availability. New loadable drivers use modules when initrd and module support
  are enabled; otherwise they are built in. Standard controller and core
  support candidates default to built in.

  Except for confirmed non-ECC memory described above, this mode only adds
  detected support: absence never removes a driver. It
  does not load/unload modules, change firmware or boot parameters, or lower
  `NR_CPUS`. Cross compilation and a different target architecture skip local
  detection. Devices unavailable to the running kernel, external drivers,
  missing alias metadata and complex Kbuild expressions can require manual
  configuration. Detection does not verify firmware installation or whether
  an initramfs contains newly enabled modules; boot verification is still needed.

  ```bash
  ./kernel-config.sh /usr/src/linux --nativer-arch --strict --dry-run
  ./kernel-config.sh /usr/src/linux --native-arch --native-cpu=on --strict
  ```

  References: [sysfs device/driver rules](https://docs.kernel.org/admin-guide/sysfs-rules.html)
  and [Kbuild module metadata](https://docs.kernel.org/kbuild/kbuild.html).

The performance-control names above remain supported. If both control families are supplied, explicit `--preemption`, `--sched-cache`, `--lru-gen`, and `--numa-balancing` settings override their corresponding `--preempt-mode`, `--sched-cache-mode`, `--mglru-mode`, and `--numa-balancing-mode` settings. Default `keep`/`none` values do not override them.

Overridden settings are skipped before applying their dependencies. RT and NUMA conflict checks also cover the legacy option names, including in `--check` mode.

- `PRUNE_OBSERVABILITY`
  Disables tracing, perf, debugfs, runtime verification, and related observability features.

- `PRUNE_LEGACY`
  Disables old compatibility options and symbols marked legacy/deprecated in Kconfig, plus reviewed help-only cases: old GPIO ABIs, HDA control identifiers and obsolete syscalls. `SGETMASK_SYSCALL` is retained with a message when its prompt is hidden by `EXPERT=n`; the script does not enable `EXPERT` implicitly. Preserves `CRYPTO_USER_API*`: a deprecation label does not establish that AF_ALG is unused. Obsolete algorithms have a separate explicit control below.

  Migrates enabled aliases `HID_THINGM`, `AK09911`, Tegra/OMAP USB aliases and four deprecated Intel GLK/CML audio options to their Kconfig-documented replacements. The replacement remains at least as available (`y`/`m`) as the former alias. Protected aliases, aliases selected by retained drivers, unavailable replacements and protected incompatible replacements are retained. Use explicit symbol lists for an audited removal without migration.

  Preserves `DRM_FBDEV_EMULATION`, whose legacy-labelled prompt still supplies the framebuffer console for DRM drivers.

  From Linux 7.4, which deprecates `SYSFB_SIMPLEFB`, moves simpledrm users to its documented replacements: `DRM_EFIDRM` (with EFI) and `DRM_VESADRM` (on x86), at the level of `DRM_SIMPLEDRM`, so the early console (initramfs prompts, a rescue shell over a BMC) survives. A console on the fbdev simplefb driver keeps `SYSFB_SIMPLEFB`; with no user it is simply disabled.

  Keeps `CEPH_FS_INLINE_DATA` (7.4+, deprecated, default `n`) as the baseline has it. Without it the CephFS client takes every inode as having no inline data, so a file whose data is still inline in the MDS reads empty without an error; it is only enabled for such a filesystem. The `ceph` profile reports when it is off, so `ceph fs get <fs>` can be checked (`inline_data disabled`) and old inline files uninlined with an MDS scrub before moving a client to 7.4.

  Preserves `DRM_AMD_DC_DCE` (7.4+, "AMD DC support for legacy DCE ASICs"): it is the display support of DCE 8-12 GPUs such as Polaris and Vega, unconditional before 7.4.

- `PRUNE_DEBUG_TRACE`
  Disables debug and trace options discovered from Kconfig prompts, plus explicit exceptions such as `DAMON_DEBUG_SANITY`, `SLUB_STATS`, `ZRAM_MEMORY_TRACKING` and `DM_DEBUG_BLOCK_MANAGER_LOCKING` (prompt "Block manager locking": lock checks on every dm-thin and dm-cache metadata access). It also disables runtime verification. Prompts that only name tracing as one user are kept: `IP_NF_RAW` and `IP6_NF_RAW` ("required for NOTRACK/TRACE") hold the Docker 28+ raw-table rules, while the `TRACE` target itself is pruned. The `server` profile, applied after the prunes, brings back the soft-lockup and hung-task detectors.

- `PRUNE_RUNTIME_VERIFICATION`
  Disables `CONFIG_RV`, removing its dependent monitors after Kconfig normalization. Also included in observability/debug pruning, since RV can select tracing support.

- `PRUNE_HARDENING`
  Disables hardening and mitigation symbols discovered from Kconfig prompts (switching the stack-initialization and struct-layout-randomization choices to `INIT_STACK_NONE` and `RANDSTRUCT_NONE` unless a sibling choice member is protected), plus runtime-cost randomization that pattern discovery misses: `RANDOMIZE_KSTACK_OFFSET_DEFAULT`, `SLAB_FREELIST_RANDOM`, `SLAB_FREELIST_HARDENED`, `SHUFFLE_PAGE_ALLOCATOR`, `RANDOM_KMALLOC_CACHES` / `KMALLOC_PARTITION_*`, `PAGE_TABLE_CHECK`.

- `PRUNE_SELFTEST`
  Disables selftests and test-only options discovered from Kconfig prompts, plus reviewed exceptions including `IO_URING_MOCK_FILE`, `CRYPTO_BENCHMARK`, `MMC_TEST`, `IOMMUFD_TEST`, `HVC_UDBG` and `NFSD_FLEXFILELAYOUT`.

- `PRUNE_SANITIZERS`
  Disables sanitizer-related options such as KASAN, KCSAN, UBSAN, KCOV, and KMEMLEAK.

- `PRUNE_COVERAGE`
  Disables gcov coverage and profiling options.

- `PRUNE_FAULT_INJECTION`
  Disables fault-injection and forced-failure testing options.

- `PRUNE_DANGEROUS`
  Disables symbols whose Kconfig prompt is explicitly marked `DANGEROUS` or `unsafe`, plus reviewed help-only risks: forced module loading/unloading, raw CXL commands, destructive MMC tests, IOMMUFD tests, experimental AT91 I2C slave support and the testing-only NFS flexfile server.

- `PRUNE_UNUSED_MODULES`
  Probes direct `CONFIG_*=m` module mappings that are not currently loaded. It disables symbols only when the module fails to load or does not remain initialized after probing; if the module is simply unused but loadable, it is only reported.
  Module-name comparisons normalize `-` and `_` so Kbuild names like `kvm-amd` still match runtime names such as `kvm_amd`.

Automatic discovery-based pruning scans common files, the generic `arch/Kconfig`, and the target `arch/<target>/` tree resolved from `ARCH` or `uname -m` (ignoring prompts from other architectures), and only edits boolean/tristate options with a prompt for the target architecture. Hidden capabilities, `ARCH_*`/`HAVE_*` symbols, and numeric/string values are skipped. Simple prompt guards such as `if EXPERT` are checked against the working configuration; complex guards are conservatively left for explicit controls. Options selected by retained enabled features are preserved, including transitive selections. Conditional selects are treated conservatively as potentially active. The kernel's `olddefconfig` still resolves dependencies and selections.

The readers accept single/double quoted prompts and escaped quotes, including separate prompts on `def_bool`/`def_tristate` declarations. Help text is never used as a blanket removal rule. `BROKEN` references, compatibility hardware, `MEDIA_TEST_SUPPORT`, raw mounted-block writes and TTL manipulation remain subjects for review, since their meaning depends on the configuration or workload.

### Read-only Kconfig audit

`--audit-kconfig` reports prompt labels, help warnings and references to `BROKEN`. It exits without applying tuning flags, inspecting initramfs producers, invoking `make` or probing modules. It works on reference-only snapshots and needs Python 3.11+ with the accompanying `lib/kconfig_audit.py`. No report is written unless you redirect stdout.

```bash
./kernel-config.sh --audit-kconfig ./linux-7.2.8
./kernel-config.sh --audit-kconfig --config-file=/usr/src/linux/.config ./linux-7.2.8
python3 lib/kconfig_audit.py --kernel-srcdir ./linux-7.2.8 --arch all --format json > audit.json
```

By default the audit scans common files and the host's architecture directory (`ARCH` overrides it). A supplied relative config path is relative to the selected tree; otherwise that tree's `.config` is used if available. Values describe that file, not the running kernel. Without a config, activation is unknown. Other architecture directories and Kconfig parser test fixtures are excluded unless appropriate; `--arch all` includes every architecture.

This is a textual report: it does not evaluate `source`, dependency expressions, selections or reachability. A help reference may describe a replacement or mitigation, and a `BROKEN` expression may allow the current architecture. Every result requires context; none is automatically classified as safe to remove.

### Module and protocol risk controls

These options accept `keep`, `on`, `off` through CLI, environment variables or `VAR=VALUE`. All default to `keep`, preserving the baseline or earlier pruning choice. Explicit settings override pruning; symbol lists apply last. Protected values and final `--strict` verification still apply.

| CLI option | Variable | Effect |
| --- | --- | --- |
| `--module-force-load` | `MODULE_FORCE_LOAD` | Controls loading modules without version information. `on` requires existing `MODULES=y`. |
| `--module-force-unload` | `MODULE_FORCE_UNLOAD` | Controls forced unloading of modules with active users. `on` requires existing `MODULES=y` and `MODULE_UNLOAD=y`. |
| `--nfs-udp` | `NFS_UDP` | Controls client UDP transport: `off` requests `NFS_DISABLE_UDP_SUPPORT=y`; `on` requests `n`. Requires existing NFS client support (`y` or `m`), including support enabled by an application profile. Review legacy UDP mounts first. |
| `--obsolete-crypto` | `OBSOLETE_CRYPTO` | Controls `CRYPTO_USER_API_ENABLE_OBSOLETE`, independently of AF_ALG interfaces. Removing old algorithms can affect clients or access to existing encrypted data. |

The `nfs-server` application profile no longer enables `NFSD_FLEXFILELAYOUT`, whose Kconfig describes a client-testing implementation unsuitable for production. An already-enabled baseline is retained unless explicitly pruned. For intentional testing, use `--enable-symbols=NFSD_FLEXFILELAYOUT` with the appropriate NFS dependencies. Dangerous/selftest pruning disables it unless overridden explicitly.

```bash
./kernel-config.sh --dry-run --strict --module-force-load=off \

```

### Explicit symbol lists

- `--disable-symbols LIST` / `DISABLE_SYMBOLS`: request `n` for the listed boolean/tristate options.
- `--module-symbols LIST` / `MODULE_SYMBOLS`: request `m` for tristate options; module support must be enabled.
- `--enable-symbols LIST` / `ENABLE_SYMBOLS`: request `y` for boolean/tristate options.

Lists are comma-separated and default to `none`. Names are case-sensitive, with an optional `CONFIG_` prefix. For example, `SND_SOC_AMD_ACP3x` contains a lowercase `x`; it is distinct from `SND_SOC_AMD_ACP3X`. The same case preservation applies to protected symbols, discovery, module mappings, validation, and dry-run output.

These lists apply after profiles and other tuning controls. Enabling a parent that a profile pruned restores only the parent: its children that were already requested off stay off (`--enable-symbols=DEBUG_FS` under `--all-optimizations` keeps `BLK_DEBUG_FS=n`). Conflicting requests for the same symbol are rejected. Protected symbols remain protected, and `--strict` rejects requests that Kconfig cannot retain. When a request does not survive `olddefconfig`, the diagnostic lists the `depends on` terms that evaluate to `n` in the final configuration, for example `Unmet request: CONFIG_EDAC requested=y final=n (check Kconfig dependencies/choices; depends on HAS_IOMEM && EDAC_SUPPORT && RAS; unmet: RAS=n)`; a reverted disable request names its active selectors instead. The hint evaluates symbol terms, `!`, `&&`, `||` and parentheses; comparisons and conditions inherited from `if`/`menu` blocks are not evaluated. Non-toggle options cannot be changed through these lists. The options configure a future kernel build; they do not unload, blacklist, install, or delete modules from the running system.

```bash
# Preview an audited removal while retaining the required audio drivers.
./kernel-config.sh --dry-run --strict \
  --disable-symbols=SND_SOC_AMD_ACP3x,SND_SOC_AMD_ACP5x /usr/src/linux
```

### Scheduler, memory, and I/O controls

All controls in this table default to `keep`: they add no request of their own, leaving the baseline or profile selection in place. They accept CLI flags, environment variables, and `VAR=VALUE` arguments. For example, `--tick-mode=idle` corresponds to `TICK_MODE=idle`.

| CLI option | Values | Effect |
| --- | --- | --- |
| `--preemption` | `keep`, `none`, `voluntary`, `full`, `lazy`, `rt` | Selects the preemption model. Availability depends on architecture and kernel version. |
| `--preempt-dynamic` | `keep`, `on`, `off` | Controls dynamic preemption independently of the model. |
| `--uclamp` | `keep`, `on`, `off` | Controls `UCLAMP_TASK`; `on` also enables `CPU_FREQ` and its schedutil build dependency, including on baselines without CPU frequency scaling, plus `UCLAMP_TASK_GROUP` when CPU cgroups are enabled. Does not change the running governor or set utilization policies. |
| `--autogroup` | `keep`, `on`, `off` | Controls `SCHED_AUTOGROUP`, overriding profile defaults. |
| `--tick-mode` | `keep`, `periodic`, `idle`, `full` | Selects exactly one of `HZ_PERIODIC`, `NO_HZ_IDLE`, or `NO_HZ_FULL`. |
| `--thp` | `keep`, `off`, `always`, `madvise`, `never` | Controls transparent huge pages and their default policy. `off` removes support; `never` retains support with a disabled default. |
| `--lru-gen` | `keep`, `on`, `off` | Controls multigenerational LRU support and its default activation. |
| `--zswap` | `keep`, `on`, `off` | `on` requests swap support, zswap, and default activation; `off` removes zswap support. |
| `--zswap-compressor` | `keep`, `lzo`, `lz4`, `lz4hc`, `zstd`, `deflate`, `842` | Enables zswap support and selects its default compressor, overriding the optimization preset. |
| `--zram` | `keep`, `off`, `module`, `builtin` | Controls zram support and whether it is built into the kernel or a module. |
| `--zram-compressor` | `keep`, `lzo-rle`, `lzo`, `lz4`, `lz4hc`, `zstd`, `deflate`, `842` | Enables the corresponding backend and selects the default compressor. Retains other backends. |
| `--numa-balancing` | `keep`, `on`, `off` | `on` requests NUMA, page migration, automatic balancing support, and default activation. |
| `--kmalloc-partition` | `keep`, `off`, `random`, `typed` | Controls slab-cache partitioning, using the legacy random-cache option on older kernels. |
| `--tcp-congestion` | `keep`, `cubic`, `bbr`, `reno` | Sets the default TCP congestion algorithm and builds in the selected implementation. BBR also enables FQ support. |
| `--default-qdisc` | `keep`, `pfifo_fast`, `fq`, `fq_codel`, `fq_pie`, `codel`, `sfq` | Enables `NET_SCH_DEFAULT`, builds in the selected queuing discipline (plus `NET_SCH_PIE` for `fq_pie`), and sets the compiled-in default (`DEFAULT_NET_SCH`). Useful on non-systemd/OpenRC hosts without a `sysctl.d` override for `pfifo_fast`, or paired with `--tcp-congestion=bbr` (`fq`). |
| `--io-uring` | `keep`, `on`, `off` | Controls io_uring support. Disabling it requires `CONFIG_EXPERT=y` in the input configuration. |

An explicit unsupported request is reported; `--strict` prevents saving it. Kconfig remains responsible for architecture and compiler capabilities. The script does not force capability symbols such as `CC_HAS_ALLOC_TOKEN`; `typed` partitioning requires compiler support. On 7.2 it uses `KMALLOC_PARTITION_CACHES` and its mode choice rather than the transitional `RANDOM_KMALLOC_CACHES` symbol. NUMA balancing uses `NUMA_MIGRATION` where available and `MIGRATION` on older trees.

RT preemption requires its existing architecture/`EXPERT` prerequisites and disables incompatible THP and NUMA balancing requests. Explicit RT plus enabled THP or NUMA balancing is rejected before editing. Dynamic preemption is a separate setting; an unsupported combination is diagnosed after `olddefconfig`. Full tickless operation still needs the appropriate boot configuration.

RT or `--thp=off` also supersedes profile requests for the persistent huge zero folio. Selecting `--tick-mode=idle` or `periodic` allows Kconfig to remove profile RCU offload settings when `RCU_EXPERT` is disabled. Explicit symbol overrides still apply last and remain subject to strict validation.

`--zram=module` requires existing module support. Specifying only a zram compressor preserves an existing module; otherwise it requests built-in zram. Specifying a compressor together with `--zram=off` or `--zswap=off` is rejected. `--numa-balancing=on` also conflicts with NUMA support resolved to `off`.

These options change kernel build configuration and defaults. They do not create swap devices, change running sysctls, select a live network qdisc, or edit boot arguments.

### Platform and hardware filters

- `CPU_VENDOR_FILTER=none|auto|amd|intel`
  On x86, prunes options specific to the other CPU vendor, including the other vendor's cpufreq driver from `drivers/cpufreq/Kconfig.x86`, and enables the matching one (`X86_AMD_PSTATE` or `X86_INTEL_PSTATE`), plus `X86_ACPI_CPUFREQ` as its fallback: when the pstate driver refuses to load (no CPPC or HWP, firmware settings) the host would otherwise run without any cpufreq driver. acpi-cpufreq is a `late_initcall`, so the pstate driver still binds first. When targeting Intel with `CPU_IDLE` and `CPU_SUP_INTEL` enabled, it also enables `INTEL_IDLE` (native MWAIT/C-state driver with `acpi_idle` fallback), matching the symmetric pruning that `amd` already performs.
  A symbol counts as vendor-specific only when every top-level `||` alternative of its `depends on` needs that vendor, so shared mitigations such as `MITIGATION_RETBLEED` (Intel and AMD Zen 1/2) are kept.
  `CPU_SUP_INTEL`/`CPU_SUP_AMD` are only user-visible under `PROCESSOR_SELECT`, which needs `CONFIG_EXPERT=y`; when `EXPERT` is off they and the other vendor's pstate driver are left untouched (Kconfig would force them back anyway).

- `VIDEO_SUPPORT=none|auto|amd|intel|nvidia|nouveau|ast|mgag200`
  Keeps only the selected display driver stack.

  Notes:
  `amd` enables `DRM_AMDGPU` and leaves `DRM_RADEON`/`FB_RADEON` as the baseline has them.
  `nvidia` means a proprietary NVIDIA setup, so the script prunes Nouveau and the in-tree AMD/Intel stacks.
  `ast` and `mgag200` keep the Aspeed or Matrox G200 server BMC display driver and prune the desktop AMD/Intel/NVIDIA stacks.

- `UEFI_SUPPORT=none|auto|on|off`
  Keeps or prunes common EFI/UEFI kernel support.

- `INITRD_SUPPORT=none|auto|on|off`
  Keeps or prunes `CONFIG_BLK_DEV_INITRD`.

- `TPM_SUPPORT=none|auto|on|off`
  Keeps or prunes TPM support and attempts to detect TPM `1.2` or `2.0`.
  `auto` inspects `/sys/class/tpm/tpm*/device/driver` (and ACPI HID fallbacks) and enables only the detected transport driver (`TCG_CRB`, `TCG_TIS`, `TCG_TIS_SPI`, `TCG_TIS_I2C`, `TCG_XEN`, etc., plus `SPI`/`I2C` parents when needed) without forcing `TCG_VTPM_PROXY`; when a TPM is present but its transport cannot be identified, it falls back to `TCG_TIS`/`TCG_CRB` for the detected version.
  `on` keeps the generic TIS/CRB and `TCG_VTPM_PROXY` drivers. Both modes leave `TCG_TPM2_HMAC` as the baseline has it: upstream defaults to `n` because HMAC and encryption are added to every kernel-to-TPM transaction. `off` removes it with the rest of TPM support.

- `DMA_ENGINE_SUPPORT=none|auto|on|off`
  Keeps or prunes `CONFIG_DMADEVICES` based on whether the running host exposes `dmaengine` devices.

- `SERIAL_SUPPORT=none|auto` / `--serial-support=none|auto`
  Default `none` preserves the baseline. Explicit `auto` removes native UART
  drivers under `drivers/tty/serial` only on a native x86 ACPI host with no
  detected ports. It checks registered TTYs (ignoring empty 8250 slots), PCI
  communication controllers, PNP/ACPI identifiers from the target kernel,
  serdev devices, console/debug arguments and ACPI SPCR/DBG2 tables. A firmware
  UART counts as absent only with status 0. Missing inventory, virtual machines
  and cross compilation preserve the baseline; detected ports are also retained.
  An explicit enabled/module or protected active UART symbol keeps the stack.
  Requires Python 3.11+ and `lib/`. It does not disable `TTY`, USB ACM/USB serial,
  `SERIO` (also used by PS/2), `SERIO_SERPORT`, or `SERIAL_MULTI_INSTANTIATE`
  (I2C/SPI devices). Use this only for the current hardware; reconfigure before
  adding a native serial card or enabling a UART in firmware.

- `IOMMU_SUPPORT=none|auto|on|off`
  Keeps or prunes generic IOMMU support and selects `AMD_IOMMU` or `INTEL_IOMMU` from the resolved CPU vendor. `auto` keeps IOMMU support only when the host exposes `/sys/class/iommu` entries or an ACPI `DMAR`/`IVRS` table; a CPU or firmware without either (a Celeron without VT-d, for example) prunes it.

- `NUMA_SUPPORT=none|auto|on|off`
  Keeps or prunes `CONFIG_NUMA` based on currently visible NUMA nodes.

- `NR_CPUS=none|auto|<integer>`
  Sets `CONFIG_NR_CPUS` to a fixed value or to the detected host CPU count. If the config defines a valid `NR_CPUS` range, the value is clamped into that range.

- `PLATFORM_DRIVERS=none|auto`
  `auto` requests the platform drivers for which the running host shows direct evidence in `/sys` and `/proc/cpuinfo`, without running `dmidecode` or `lspci`. Default `none` changes nothing. Each request is printed with its evidence (`IPI0001:00 -> CONFIG_IPMI_SI=m`). Symbols are requested as modules when `CONFIG_MODULES=y` and the symbol is tristate, otherwise built in; an existing built-in is never demoted. Symbols missing from the kernel tree are reported as "not available in this tree" and do not fail `--strict`. Parents (`RAS`, `EDAC`, `X86_MCE`, `HWMON`, `I2C`, `WATCHDOG`, `IPMI_HANDLER`, `PCI`) are enabled first, with an intermediate `olddefconfig` when one was off.

  Evidence table (small and extensible):
  - ACPI `IPI0001` or SMBIOS type 38: `IPMI_HANDLER`, `IPMI_DEVICE_INTERFACE`, `IPMI_SI` (or `IPMI_SSIF` with `I2C` when SMBIOS type 38 reports interface type 4 / SSIF), `ACPI_IPMI`.
  - ACPI `ACPI000D` (ACPI 4.0 power meter): `SENSORS_ACPI_POWER` plus the IPMI set, because `_PMM` reads an IPMI OperationRegion; without `acpi_ipmi` the kernel logs `No handler for Region [POWR] [IPMI]` on every hwmon read.
  - `dmi/id/sys_vendor` HP/HPE: `HP_ILO`, `HP_WATCHDOG` (confirmed by PCI `103c:3306`/`103c:3307` when visible). Dell: `DCDBAS`, `DELL_SMBIOS`. Supermicro: nothing beyond IPMI.
  - With ECC evidence: Intel host bridge (PCI class `0600`, the device ids handled by `ie31200_edac`): `EDAC_IE31200`; Xeon families by CPU model: `EDAC_SBRIDGE`, `EDAC_SKX`, `EDAC_I10NM` (including Ice Lake-X/D and Snow Ridge). AMD family 0fh+: `EDAC_AMD64`, plus `AMD_ATL` on Zen when the target tree provides it. AMD `EDAC_DECODE_MCE` is requested independently of DRAM ECC because CPU/cache machine checks remain useful. The CPU vendor follows `CPU_VENDOR_FILTER` when set, so the two phases never contradict each other.
  - Intel SMBus (class `0c05`): `I2C_I801`. Intel LPC/eSPI bridge (class `0601`): `ITCO_WDT` (plus `LPC_ICH` when `EXPERT=y`; hpwdt and iTCO can coexist). AMD/ATI/Hygon FCH SMBus (`1022:790b`, `1022:780b`, `1d94:790b`, `1002:4385`): `I2C_PIIX4` and `SP5100_TCO` (because `sp5100_tco` does not bind as a `pci_driver`). CPU sensors: `SENSORS_CORETEMP` (plus `X86_PKG_TEMP_THERMAL` when every visible CPU advertises `pts` and `NET`/`X86_THERMAL_VECTOR` are enabled) or `SENSORS_K10TEMP`.

  EDAC, PCH, hwmon and watchdog detection is x86-only. `PROTECTED_CONFIG_SYMBOLS` and the explicit symbol lists still take precedence.

  DRAM ECC detection reuses the Python hardware helper. Active EDAC DIMM/rank/row
  correction modes take precedence; otherwise it reads SMBIOS types 16 and 17
  directly from `/sys/firmware/dmi/tables/DMI`. ECC correction plus DIMM check bits
  allows driver requests. Only complete, consistent records showing no ECC and
  equal total/data widths for every populated system DIMM allow removal of the
  listed memory drivers, `AMD_ATL` and `RAS_CEC`. Empty sockets do not count as
  non-ECC memory. Missing permissions, Python, firmware data or conflicting records
  mean **unknown**: no new memory-driver request and no removal of existing support.
  A CPU family or module alias alone is insufficient. SMBIOS evidence identifies
  candidates; verify controller registration after boot to confirm firmware enabled
  ECC. DDR5 on-die ECC alone does not provide system ECC. This detection does not
  load modules or enable ECC in firmware, and it preserves the EDAC/MCE core.

- `PROTECTED_CONFIG_SYMBOLS=<comma-separated-list>`
  Prevents the script from enabling, disabling, or overwriting the listed symbols. The default protected list already includes `CONFIG_ARCH_PKEY_BITS`.

### Virtualization and workload hints

- `HOST_TYPE=none|auto|baremetal|qemu|vmware|hyperv|virtualbox`
  Tunes bare-metal or guest virtualization drivers for the selected host type. `kvm` is accepted as an alias for `qemu`, and `native` as an alias for `baremetal`. `auto` inspects `/proc/cpuinfo` (`hypervisor` flag), `/sys/hypervisor/type`, DMI strings, paravirtualized buses (`vmbus`, `xen`, `virtio`, `qemu_fw_cfg`) and VMware/VirtualBox PCI devices; unknown hypervisors or incomplete inventories leave the baseline untouched.
  On x86 with `CPU_IDLE=y`, `qemu` also enables `HALTPOLL_CPUIDLE` (which selects `CPU_IDLE_GOV_HALTPOLL`) so KVM guests poll briefly before halting instead of triggering unnecessary VM-exits and remote vCPU wakeup IPIs (`Documentation/virt/guest-halt-polling.rst`); other host types prune it.
  `hyperv` also keeps the synthetic keyboard, mouse and video drivers: `DRM_HYPERV` when the baseline has DRM, otherwise `FB_HYPERV` (re-enabled even if `PRUNE_LEGACY` disabled it as deprecated).

- `APPLICATIONS=<comma-separated-list>`
  Enables kernel features commonly required by selected applications.

  Supported profiles:
  `desktop`, `multimedia`, `rocm`, `nebula`, `warp`, `samba`, `firehol`, `firewalld`, `iptables-legacy`, `openvswitch`, `ceph`, `nfs-client`, `nfs-server`, `openvpn`, `wireguard`, `docker`, `qemu`, `atop`, `bmon`, `btop`, `htop`, `iotop-c`, `cryptsetup`, `multipath`, `python`, `rasdaemon`

  - `desktop`: GNOME/Wayland interfaces, browser namespaces/seccomp, IDE file
    notifications, FUSE portals, input/HID and DRM synchronization. This enables
    capabilities; scheduling policy is selected separately with
    `--optimization-profile=desktop`.
  - `multimedia`: ALSA/high-resolution timers, USB audio, UVC cameras and HID raw
    access for userspace controllers (PipeWire, OBS and Resolve workflows).
    Existing modular audio/camera drivers remain modular. GPU drivers, codecs,
    device permissions and userspace libraries are separate requirements.
  - `rocm`: AMDGPU/KFD and HMM shared virtual memory support, including device
    memory prerequisites. Existing `DRM_AMDGPU=m` is preserved. This does not
    certify a GPU/userspace combination or install ROCm. KFD belongs to amdgpu;
    an absent standalone KFD entry in `lsmod` does not indicate missing support.
  - `nebula`: userspace VPN support through TUN. Nebula 1.11 opens
    `/dev/net/tun` (multi-queue), manages its addresses and routes over
    rtnetlink in the main table and sets `SO_MARK` on its UDP socket; it needs
    no netfilter or policy-routing support and does not use the kernel
    WireGuard driver. An IPv6 overlay also needs `IPV6`. See the
    [Nebula TUN configuration](https://nebula.defined.net/docs/config/tun/).
  - `warp`: Cloudflare WARP client (`warp-svc`). Userspace WireGuard/MASQUE
    over TUN, the `inet cloudflare-warp` nftables table (including reject
    expressions) and fwmark policy routing for IPv4 and IPv6
    (`IP_MULTIPLE_TABLES`, `IPV6_MULTIPLE_TABLES`). Client 2026.8+ installs the
    IPv6 fwmark rule unconditionally; without `IPV6_MULTIPLE_TABLES` the tunnel
    fails with "IPv6 fwmark rule install: Address family not supported by
    protocol (os error 97)". The kernel WireGuard driver is not required.
  - `python`: the options `dev-lang/python` checks (`CROSS_MEMORY_ATTACH`,
    `DNOTIFY`). Without `CROSS_MEMORY_ATTACH`, `process_vm_readv` and
    `process_vm_writev` return `ENOSYS`, and CPython 3.14+ remote debugging
    (`python -m pdb -p`, `sys.remote_exec()`) falls back to opening
    `/proc/PID/mem` read-write. The Portage sandbox denies that file during the
    `USE=pgo` profiling run, so the emerge fails right after
    "Source compiled." with an access violation on `/proc/<pid>/mem`.
    `DNOTIFY` only enables `test_fcntl`. Both default to `y` upstream and cost
    nothing until a program calls them.

  - `multipath`: device-mapper multipath, uevents and the queue-length,
    service-time, historical-service-time and I/O-affinity path selectors
    (`DM_MULTIPATH_QL/ST/HST/IOA`, where available). These are software policies,
    not drivers tied to a storage vendor. New tristate requests use modules
    when `MODULES=y`; existing built-in support is preserved. With modules
    disabled, they are built in. The profile does not create maps, start
    multipathd or require currently active paths. Vendor-specific SCSI handlers
    remain a separate hardware requirement.

  - `rasdaemon`: rasdaemon records PCIe AER, machine checks and memory errors
    from tracefs events (`ras:*`, `mce:mce_record`), so it needs `TRACING`
    even when `--all-optimizations` prunes the tracers. The profile always
    requests `FTRACE` with `ENABLE_DEFAULT_TRACERS`, which provide the events
    without the function tracer or kprobes, plus `RAS`, `PCIEAER` and
    `X86_MCE`. `PCIEAER` needs no evidence: sysfs does not show whether the
    firmware grants AER to the operating system. The other symbols serve
    consumers that only some hardware or rasdaemon releases have. Without host
    evidence the profile requests all of them; with `--platform-drivers=auto`
    (implied by `--native-arch`) it leaves one out when the evidence rules out
    every consumer:

    | Symbols | Consumer | Left out when |
    |---|---|---|
    | `EDAC` | memory controller events (`ras:mc_event`) | DRAM ECC is off |
    | `ACPI_APEI`, `ACPI_APEI_GHES` | firmware-first errors (HEST) and machine checks saved in ERST | `/sys/firmware/acpi/tables` has no `HEST` (GHES), or neither `HEST` nor `ERST` (APEI) |
    | `MEMORY_FAILURE`, `MEMORY_HOTPLUG` | memory failure events and page offlining, which uses `/sys/devices/system/memory/{soft,hard}_offline_page` (built with `MEMORY_HOTPLUG`) | DRAM ECC is off and no CXL memory device (PCI class 0502) is present |
    | `DEBUG_FS`, `DEBUG_FS_ALLOW_ALL` | rasdaemon before 1.0, which finds tracefs only at `debugfs/tracing`, and ACPI EXTLOG, which only emits events while rasdaemon holds `/sys/kernel/debug/ras/daemon_active` open | rasdaemon is 1.0 or newer and the CPU is AMD or Hygon (EXTLOG needs Intel eMCA, `MCG_ELOG_P`) or the target is not x86 |
    | `TRACEFS_AUTOMOUNT_DEPRECATED` | rasdaemon before 1.0 | rasdaemon is 1.0 or newer |

    Missing or unreadable evidence keeps the request, and each symbol left out
    is printed with its evidence. ECC comes from the same detection as the
    platform drivers. The rasdaemon release comes from `rasdaemon --version` on
    the running host; with `KC_HOST_ROOT` it stays unknown unless
    `KC_RASDAEMON_VERSION` supplies it. The profile does not disable a symbol it
    leaves out: `--all-optimizations` prunes debugfs, and the rest keep their
    baseline value. `TRACEFS_AUTOMOUNT_DEPRECATED` returns at its Kconfig default
    (`y`) whenever `TRACING` does; with rasdaemon 1.0 and a service that mounts
    `/sys/kernel/tracing`, `--disable-symbols=TRACEFS_AUTOMOUNT_DEPRECATED`
    removes that legacy automount. Without page offlining support rasdaemon
    falls back to accounting even when `PAGE_CE_ACTION=soft`. `MEMORY_HOTREMOVE`
    is not required or requested. The vendor EDAC driver (`EDAC_AMD64`,
    `EDAC_IE31200`...) comes from `--platform-drivers=auto` when memory ECC
    evidence is available.

  `firewalld` enables the nftables backend without requesting legacy-only NAT
  tables on kernels exposing `NETFILTER_XTABLES_LEGACY` (6.17+). Existing legacy
  settings are retained; `firehol` explicitly requests the legacy backend.
  `docker` follows the same rule: on 6.17+ it requests what Docker's rules need
  through iptables-nft (`NFT_COMPAT`, the `addrtype` and `conntrack` matches,
  the `DNAT`/`MASQUERADE` targets) instead of the legacy nat table, so it no
  longer conflicts with `PRUNE_LEGACY`. A host whose `iptables -V` reports
  `legacy` also needs `iptables-legacy`, which requests the legacy filter,
  mangle, raw and nat tables for IPv4 and IPv6, and the shared
  `NETFILTER_XT_TARGET_MASQUERADE` / `NETFILTER_XT_TARGET_HL` targets. These
  keep IPv4 MASQUERADE and TTL rules available even when `PRUNE_LEGACY`
  disables the `IP_NF_TARGET_MASQUERADE` / `IP_NF_TARGET_TTL` compatibility
  wrappers. The shared modules also provide the `ipt_MASQUERADE` / `ipt_TTL`
  aliases used for automatic loading. Docker 28+ writes its
  direct-access `DROP` rules to the raw table. Those tables and the xtables
  extensions of `docker` and `firehol` are loaded on demand, so they follow the
  `PLATFORM_DRIVERS` rule: built-in stays built in, otherwise a module when
  `MODULES=y`. A request therefore never exceeds a modular `NETFILTER_XTABLES`.
  `atop` builds `CONNECTOR` in, because `PROC_EVENTS` depends on `CONNECTOR=y`.
  `qemu` enables host drivers and lets Kconfig select internal VHOST dependencies
  at the required built-in/module level. Newly enabled `VFIO`, `VHOST_NET` and
  `VHOST_VSOCK` use modules when available: modular `IOMMUFD`, `TAP` or
  `VSOCKETS` dependencies prevent building those consumers into the kernel.
  Existing built-ins and explicit symbol overrides are preserved.
  `firehol` also requests the targets and matches that `firehol debug` emits for
  an ordinary configuration (`physdev`, `TCPMSS`, `DSCP`, `NETMAP`, `CT`, mark,
  limit/recent/hashlimit, the FTP helper).
  `nfs-server` does not enable the deprecated `NFSD_LEGACY_CLIENT_TRACKING`
  (6.9+). Without it nfsd logs "Unable to initialize client recovery tracking"
  unless the `nfsdcld` daemon from nfs-utils runs before nfsd; the profile prints
  a reminder, and `--enable-symbols=NFSD_LEGACY_CLIENT_TRACKING` is the kernel-side
  alternative.

  Example:

```bash
APPLICATIONS="docker,firewalld,wireguard" ./kernel-config.sh /usr/src/linux
```

### Reusable desktop example

`profiles/desktop.sh` combines the desktop scheduling profile with the
`desktop,multimedia` application profiles. It defaults to a **strict dry run**,
accepts the same arguments as `kernel-config.sh`, and lets trailing options
override its defaults. Hardware selection, CPU count, firmware, boot/storage
requirements and additional applications are left to the target configuration
and the caller's explicit options.

```bash
./profiles/desktop.sh /path/to/linux
# Add the application profiles needed by the target system:
./profiles/desktop.sh /path/to/linux --applications=desktop,multimedia,qemu
# Save to a separate existing copy of the baseline for review:
cp /path/to/linux/.config /tmp/desktop.config
./profiles/desktop.sh /path/to/linux /tmp/desktop.config --dry-run=false
```

Select `rocm` only for an AMD GPU compute workload, and select VPN, filesystem
or virtualization profiles according to the target's requirements. The example
does not prescribe a CPU/GPU vendor, motherboard sensor, fixed CPU count or
list of drivers to discard. Existing environment-variable defaults still apply
as documented under Usage.

Saving changes a kernel configuration, not the running kernel. Build/install,
initramfs generation and a reboot are separate steps. Even a dry run can update
Kconfig build tools in the selected source tree. Performance and bootability
must be validated on the resulting kernel.

### Reusable KVM server example

`profiles/server-kvm-host.sh` combines the server scheduling profile with
`--all-optimizations` (and therefore its full pruning set, see
`ALL_OPTIMIZATIONS`), the `qemu,docker` application profiles, bare-metal host
type and the hardware filters in `auto` mode. It also defaults to a **strict dry run** and accepts trailing
overrides. Run it on the target host so the `auto` detections see the real CPU,
firmware, NUMA and DMA engines. It enables `MAGIC_SYSRQ` (kept for console
emergencies, with `MAGIC_SYSRQ_SERIAL` off) and disables
`RCU_NOCB_CPU_DEFAULT_ALL` (offloading RCU callbacks on every CPU, including a
VM host that never sets `nohz_full=`; the server profile disables it too). Both are set
explicitly rather than protected, so a baseline left by an earlier run, where
the pruning had already removed SysRq or an older server profile had turned
the offload on, converges to the same result. A trailing `--enable-symbols` or
`--disable-symbols` replaces these lists; repeat their entries when passing
your own. The profile still turns the offload off if that entry is dropped.

```bash
./profiles/server-kvm-host.sh /usr/src/linux
# Add the firewall backend and file services; Docker on iptables-legacy also
# needs iptables-legacy. Keep 32-bit binaries running:
./profiles/server-kvm-host.sh /usr/src/linux \
  --applications=qemu,docker,iptables-legacy,firewalld,nfs-server,nfs-client,cryptsetup \
  --prune-compat32=false --initrd-compression=auto
./profiles/server-kvm-host.sh /usr/src/linux --dry-run=false
```

`--all-optimizations` switches the kernel image to zstd; with
`--initrd-compression=auto` (add it on hosts that have genkernel or ugrd) the
initramfs compatibility report tells whether the installed generator still
produces something the kernel can unpack. Pass `--kernel-compression=keep` after
the profile to leave the image format alone.

### One config for identical hosts

Hosts that share hardware and role drift apart when each kernel is configured
on its own: same-model servers configured months apart can end up with
different timer rates, preemption models, compression and SysRq settings. To
converge them on one config:

1. Collect each running config (`/proc/config.gz`) and normalize every copy on
   the same target tree with `make KCONFIG_CONFIG=<copy> olddefconfig`.
   Differences caused only by kernel versions disappear; the rest are real
   choices. Do it in a writable copy of the tree: `cc-option` probes fail in a
   root-owned one. A 6.16-or-older baseline loses the legacy iptables tables
   on 6.17+ (`NETFILTER_XTABLES_LEGACY=n`), so compare `iptables -V` on every
   host first.
2. Start from the baseline that is already closest to the target and run the
   profile with explicit values instead of `auto`: `--cpu-vendor-filter`,
   `--uefi-support`, `--tpm-support`, `--iommu-support`, `--numa-support`,
   `--dma-engine-support`, and `--nr-cpus` of the largest host.
3. Pass the union of the hosts' applications, and keep each host's own
   hardware with `--enable-symbols` or `--module-symbols`, for example a SAS
   HBA or XFS quotas that only one host uses.
4. Use `--native-cpu=on` only when every host has the same CPU generation and
   the kernel is built on one of them.
5. Check the result against the modules each host has loaded (`lsmod`). Before
   installing, check every host's initramfs generator and compression: a
   zstd-only kernel does not boot from the XZ image that an unconfigured
   genkernel or ugrd still produces. With the new config in place,
   `kernel-config.sh --check --strict` on each host reports it.

### Hardware as a regression reference

Real desktops provide test cases for the general-purpose tool. Findings from
one machine should become reproducible tests and improvements to shared
profiles, rather than universal assumptions about other users' hardware.
The desktop validation exercised these cases:

- Built-in storage, network and audio drivers are absent from `lsmod`; unloaded
  USB audio/camera modules can still be needed when peripherals are connected.
  Neither case justifies removing support automatically.
- AMDGPU contains KFD support. Preserve modular GPU drivers while enabling
  compute capabilities, and distinguish userspace ICD/library errors from
  missing kernel drivers.
- Application profiles must restore disabled parent subsystems and preserve
  explicit overrides and protected symbols.
- Kconfig selects internal VHOST dependencies at the level required by their
  consumers. Profiles should request the public drivers instead of pinning
  hidden dependencies to the baseline's module level.
- The Intel TSX `off` choice can exist on AMD targets. Vendor filtering must
  not request removal of every member of that choice.
- Modern nftables support does not require enabling legacy-only NAT tables.
  Tests cover the distinction from older kernels.
- Motherboard sensors require a supported device/board match. Missing a sensor
  module on a reference machine does not justify enabling it for all desktops.
- A kernel default governor is distinct from the active policy chosen by
  drivers and userspace power management. Configuration changes alone do not
  establish a measured performance improvement.

Integration tests use temporary copies of a supplied kernel tree and baseline;
local observations and generated candidate configs belong under ignored
`reports/`. Reference artifacts are test evidence, not recommended configs for
other machines. Keep machine names out of shared examples and report names.

### Additional pruning toggles

- `PRUNE_BPF`
- `PRUNE_COMPAT32`
- `PRUNE_UNUSED_NET`
- `PRUNE_UNUSED_MODULES`
- `PRUNE_OLD_HW`
- `PRUNE_X86_OLD_PLATFORMS`
- `PRUNE_LEGACY_ATA`
- `PRUNE_INSECURE`
- `PRUNE_RADIOS`
- `PRUNE_DMA_ATTACK_SURFACE`

These are narrower switches for optional subsystems and aggressive cleanup.

Their fixed lists keep any symbol that an enabled feature selects, as discovery-based
pruning does (`Retaining CONFIG_MPLS: selected by enabled CONFIG_OPENVSWITCH`):
`olddefconfig` would turn it back on and `--strict` would reject the run.

`PRUNE_UNUSED_MODULES` is intentionally conservative: it requires root, the target tree's `kernelrelease` to match the running kernel, and only handles direct one-symbol/one-module `obj-$(CONFIG_FOO) += foo.o` mappings.

## Auto-Detection Behavior

Several parameters support `auto`. Current detection logic is intentionally simple and host-based.

- `CPU_VENDOR_FILTER=auto`
  Reads `/proc/cpuinfo`.

- `VIDEO_SUPPORT=auto`
  Tries `/sys/class/drm` first, then falls back to PCI vendor detection (AMD, Intel, NVIDIA, Aspeed `ast`, Matrox `mgag200`).

- `HOST_TYPE=auto`
  Reads `/proc/cpuinfo`, `/sys/hypervisor/type`, `/sys/class/dmi/id/*`, `/sys/bus/{vmbus,xen,virtio}/devices`, `/sys/firmware/qemu_fw_cfg` and VMware/VirtualBox PCI IDs; returns `unknown` (no changes) when virtualized on an unsupported hypervisor or when host identity is incomplete.

- `UEFI_SUPPORT=auto`
  Checks `/sys/firmware/efi`.

- `INITRD_SUPPORT=auto`
  Tries boot parameters from `/sys/kernel/boot_params/data`, with a fallback to `initrd=` in `/proc/cmdline`.

- `TPM_SUPPORT=auto`
  Checks `/sys/class/tpm/tpm*` and tries to identify version `1.2` or `2.0`.

- `DMA_ENGINE_SUPPORT=auto`
  Checks for devices under `/sys/class/dma`.

- `IOMMU_SUPPORT=auto`
  Checks `/sys/class/iommu/*`, then the ACPI `DMAR` (Intel VT-d) or `IVRS` (AMD-Vi) table under `/sys/firmware/acpi/tables`; without either it resolves to `off`. The vendor driver is still chosen from the CPU vendor.

- `PLATFORM_DRIVERS=auto`
  Reads `/sys/bus/acpi/devices`, `/sys/firmware/dmi/entries`, `/sys/class/dmi/id/sys_vendor`, `/sys/bus/pci/devices/*/{vendor,device,class}` and `/proc/cpuinfo`. All of these are world-readable; root is not required.

- `NUMA_SUPPORT=auto`
  Checks `/sys/devices/system/node`.

- `NR_CPUS=auto`
  Uses CPU topology from `/sys/devices/system/cpu`, then falls back to `getconf`, `nproc`, or `/proc/cpuinfo`.

- XFS feature checks
  If XFS is present and mounted, the script inspects mounted filesystems with `xfs_info` and toggles:
  `CONFIG_XFS_SUPPORT_V4`
  `CONFIG_XFS_SUPPORT_ASCII_CI`

`KC_HOST_ROOT=/path` prefixes every `/sys` and `/proc` read used by auto-detection and is passed to the initramfs inspector as its `--host-root` (its `/etc`, `/proc/self/mountinfo` and `/sys/class/block`). Native device discovery also reads the capture's `/proc/sys/kernel/osrelease` and `/lib/modules/<release>/modules.alias`, `modules.builtin` and `modules.builtin.modinfo`; it resolves captured sysfs links within that root and never falls back to live module metadata for an offline capture. It exists for the test suite and for offline analysis of a captured sysfs; it is not a tuning option, and tools such as `findmnt`, `nproc` or `xfs_info` still see the real host. A capture cannot run its own `rasdaemon --version`, so `KC_RASDAEMON_VERSION` (for example `1.0.0`) gives the `rasdaemon` profile the release installed on the captured host.

Important limitation:

Auto-detection only sees the currently running host. It does not try to infer hardware that is absent, unplugged, disabled in firmware, or not visible to the running kernel.

## Output and Safety

The script:

- validates inputs before editing a temporary copy
- stops on `scripts/config`, config-read, or `olddefconfig` errors
- prints each symbol it enables or disables
- reports requested values that did not survive `make olddefconfig`
- detects changes to the original config before committing and refuses to overwrite them
- creates a unique backup named like `.config.bak.YYYYMMDD-HHMMSS.XXXXXX` immediately before saving
- atomically replaces the target, preserving ownership/permissions and resolving config symlinks to their target
- cleans its temporary config, `.old` file, and directory on success, failure, SIGINT, or SIGTERM
- skips backups and replacement when the normalized config is already identical
- prints a suggested `diff` command after saving

Both modes print a compact `CONFIG_FOO: old -> new` summary instead of a unified diff; when saving, it appears before the backup path and the suggested `diff` command.

With `VALIDATION_MODE=strict` or `--strict`, a mismatch exits with status 1 before
creating a backup or replacing the original config, including normal runs.

A symbol the script disabled that disappears from the config after `make olddefconfig`
(because its dependency was also disabled) counts as satisfied, not as a mismatch.

If `PRUNE_UNUSED_MODULES` is enabled, the script temporarily probes unloaded modules and then restores the loaded-module set back to its initial state before continuing.
Restoration is attempted even if loading a module fails. If restoration fails, the script aborts without saving the configuration and attempts restoration again during cleanup. `--dry-run` skips active probes entirely.

Recommended review flow:

```bash
diff -u /path/to/.config.bak.TIMESTAMP /path/to/.config | less
```

If your kernel tree provides it:

```bash
scripts/diffconfig old.config new.config
```

## Kernel Version Compatibility

The script targets Linux 6.12 and newer. Every symbol goes through a presence check
against the target Kconfig definitions, so profile symbols that do not exist in a given tree are skipped.
Explicit unsupported requests are reported and rejected in strict mode. The fixed symbol lists keep names that still exist in 6.12 LTS but were
removed later, annotated in the script with the removal version:

| Symbol | Last version | Replacement / note |
| --- | --- | --- |
| `USELIB` | 6.14 | none (syscall removed) |
| `LIBCRC32C` | 6.14 | `CRC32`, promptless and selected by `CEPH_LIB` |
| `SCHED_DEBUG` | 6.14 | always on since 6.15 |
| `IP_DCCP` | 6.15 | none (protocol removed) |
| `CRYPTO_CURVE25519` | 6.17 | `CRYPTO_LIB_CURVE25519`, promptless and selected by `WIREGUARD` |
| `NFS_V4_1` | 6.19 | folded into `NFS_V4`; `NFS_V4_2` remains |
| `ATALK`, `CAIF`, `HAMRADIO`, `NF_CT_PROTO_UDPLITE`, `X86_RDC321X` | 7.0 | none (subsystems removed) |
| `FB_HYPERV` | 6.19 | `DRM_HYPERV` (the `hyperv` host type keeps whichever exists) |
| `HYPERV_IOMMU` | 7.0 | built unconditionally with `HYPERV` |
| `RANDOM_KMALLOC_CACHES` | 7.0 | `KMALLOC_PARTITION_CACHES` / `_RANDOM` / `_TYPED` |
| `HAVE_PREEMPT_DYNAMIC` | 7.3 | `ARCH_HAS_PREEMPT_LAZY` gates `PREEMPT_DYNAMIC` from 7.4 |

Symbols the script uses that only exist in newer trees (`NO_PAGE_MAPCOUNT` and
`DETECT_HUNG_TASK_BLOCKER` 6.15+, `X86_NATIVE_CPU` 6.16+, `NETFILTER_XTABLES_LEGACY`
6.17+, `PERSISTENT_HUGE_ZERO_FOLIO` and `CRC_OPTIMIZATIONS` 6.18+, `RSEQ_SLICE_EXTENSION` 7.0+, `SCHED_CACHE`,
`NUMA_MIGRATION` and `KMALLOC_PARTITION_*` 7.2+) are no-ops on older kernels; conversely,
`SLUB_CPU_PARTIAL` is tuned on 6.12–6.18 LTS trees and skipped automatically on 7.2+ trees where slab sheaves replaced per-CPU partial slabs.

### HugeTLB vmemmap optimization before 7.2

On every run, a tree older than Linux 7.2 gets
`HUGETLB_PAGE_OPTIMIZE_VMEMMAP_DEFAULT_ON` disabled. The version comes from
`VERSION`/`PATCHLEVEL` in the tree's `Makefile`; if it cannot be read, the tree is
treated as older. An explicit `--enable-symbols` request for it is reported as an
unmet request (and rejected with `--strict`) instead of being applied. Listing it in
`--protected-config-symbols` keeps an enabled value, but it is reported the same
way. From 7.2 the baseline value is kept and the option can be requested.

The reason is a bug in the 6.18 stable series. 6.18.51 brought in part of the HVO
rework: it dropped the step that cleaned up the restored `struct page`s, but not
the zeroed shared tail page that makes that step unnecessary in 7.2. When a HugeTLB
page goes back to the buddy allocator, the head `struct page`s are copied into the
tail ones, and one of them keeps the folio's page count where `memcg_data` lives
(`0x200` for 2 MB). Later the kernel takes that value for a memory cgroup and oopses
in `uncharge_folio`, typically hours after the HugeTLB pages were released. Booted
with `init_on_free=1`, reserving and releasing 2 MB pages makes 6.18.57 report
`BUG: Bad page state` (`page still charged to cgroup`, `corrupted mapping in tail page`).
6.12.41, 6.18.12, 6.19.6, 7.0.14 and 7.2.0 report none. Kconfig cannot tell
the affected trees apart, so the script gates by version.

The option only sets the default. HVO itself (`HUGETLB_PAGE_OPTIMIZE_VMEMMAP`)
stays built and can still be turned on with `hugetlb_free_vmemmap=on` or the
`vm.hugetlb_optimize_vmemmap` sysctl. On an affected kernel, keep it off before
reserving HugeTLB pages that may be released later. Without the default, HVO no
longer saves about 28 KiB of `struct page` memory per 2 MB HugeTLB page.

## Caveats

- This script is opinionated. Review the final config before using it in production.
- `PRUNE_HARDENING` reduces security hardening.
- `NATIVE_CPU=on` produces a kernel that may not boot on a different CPU model.
- `PRUNE_LEGACY` may remove compatibility features you still depend on.
- `PRUNE_SANITIZERS`, `PRUNE_COVERAGE`, and `PRUNE_FAULT_INJECTION` remove test-oriented instrumentation.
- `PRUNE_DANGEROUS` removes edge-case options that upstream Kconfig labels as dangerous or unsafe, such as late microcode loading or risky device/debug paths.
- `PRUNE_UNUSED_MODULES` uses a host/runtime heuristic. It only auto-disables modules that fail to load or do not stay initialized during probing; modules that are merely unused but loadable are reported and kept.
- Application profiles enable common requirements, not every optional kernel feature that a project can use.
- `HOST_TYPE` and `APPLICATIONS` can re-enable symbols after broader pruning phases.
- Profiles preserve symbols that the baseline builds as modules (`=m`), including drivers that load firmware from the root filesystem (`amdgpu`, `iwlwifi`). Explicit built-in requests such as `--enable-symbols` or `--zram=builtin` take precedence.
- The `firehol` and `iptables-legacy` profiles keep the iptables-legacy tables (`NETFILTER_XTABLES_LEGACY`, `IP_NF_IPTABLES_LEGACY`, `IP6_NF_IPTABLES_LEGACY` and the filter/mangle/raw/nat tables) that `PRUNE_LEGACY` would otherwise disable; `firehol` adds the xtables targets and matches its generated rules use. `NETFILTER_XTABLES_LEGACY` depends on `!PREEMPT_RT`, so the legacy backend is unavailable on RT kernels.
- When a profile enables a symbol that was off in the baseline (for example `ZSWAP` or `LRU_GEN`), the script runs an intermediate `make olddefconfig` so the symbols that depend on it become visible and can be configured in the same run.
- Application profiles do not pin symbols without a prompt (`SUNRPC`, `LOCKD`, `GRACE_PERIOD`, `TRACING`...): those take the level of the options that select them, so keeping `SUNRPC=m` from a modular NFS client while `nfs-server` builds `NFSD` in would fail. The script drops them, with any earlier request, and lists them in the output.
- An application profile that turns a pruned parent back on (`FTRACE` for `rasdaemon`) applies the earlier disable requests again to the children that reappear at their Kconfig default, such as `UPROBE_EVENTS=y`; the symbols the profile requests itself are exempt.
- `PROTECTED_CONFIG_SYMBOLS` blocks direct script edits. Changes caused by `make olddefconfig` are reported; `--strict` prevents saving them.
- Symbol availability is checked against Kconfig definitions, including symbols absent from the baseline `.config`. The final Kconfig result remains authoritative for architecture, visibility, and dependencies. Kconfig metadata covers the common files, the generic `arch/Kconfig` and the `arch/<target>/` tree resolved from `ARCH` or `uname -m`; other architectures are excluded.
- `PLATFORM_DRIVERS=auto` only sees hardware the running kernel exposes; a board whose BMC is disabled in firmware, or a kernel without ACPI, produces no IPMI evidence.
- Some symbols are architecture-specific, so results depend on the target kernel tree and baseline config.

## Download Kconfig reference snapshots

`download-kconfig.py` queries [kernel.org release metadata](https://www.kernel.org/releases.json)
for the latest stable releases in the 6.12.x and 6.18.x branches and the current
mainline release (including release candidates). It needs Python 3.11.8+ with
`tarfile` extraction filters and XZ support; no third-party Python packages are needed.

```bash
./download-kconfig.py                 # create linux-VERSION folders here
./download-kconfig.py /path/to/copies  # use another parent directory
```

Each folder preserves every `Kconfig*` file at its original path and the complete
`Documentation/` subtree, including hidden files, links and empty directories.
Other files and empty directories outside `Documentation/` are omitted during
extraction. These are reference snapshots, not buildable kernel source trees.

Existing destination folders or links cause an error before downloading any
archives; they are never replaced. Downloads and extraction use temporary storage
that is cleaned up on failure. A completed snapshot remains available if a later
download fails. Generated `linux-*` folders are already ignored by Git.

## Tests

The regression suite uses temporary kernel fixtures and substitutes `make`, `scripts/config`, and module probes. It never loads or unloads real modules.

```bash
bash -n kernel-config.sh
shellcheck kernel-config.sh
bash tests/test-performance-controls.sh
python3 -m unittest discover -s tests -v
```

Optional integration tests run the real `olddefconfig` target from a complete kernel tree with a baseline `.config`:

```bash
KERNEL_TEST_SRCDIR=/path/to/linux python3 -m unittest discover -s tests -v
```

The integration tests copy configuration/build tooling and generated includes into a temporary tree, link the other source paths, and verify that the supplied source `.config` is unchanged. The 7.2 checks exercise preemption/RT, tick choices, THP, LRU, zswap/zram, NUMA migration, kmalloc partitioning, BBR, io_uring, runtime verification, `SCHED_CACHE`, and initrd decoding. They also check strict rejection, dry-run, idempotence, module/NFS risk controls, the NFS server profile, deprecated aliases, quoted Netfilter prompts and EXPERT-gated pruning. Reference-only Kconfig snapshots do not replace these integration tests.

Host detection tests build a synthetic `/sys` and `/proc` under `KC_HOST_ROOT` (UEFI, DMA engines, NUMA nodes, IOMMU units and ACPI tables, ACPI/DMI/PCI platform-driver evidence). Compression tests use isolated builder metadata and synthetic CPIO streams, including concatenation, early microcode, CRC64 rejection, truncated streams, absent dependencies, ambiguous generators, strict rollback, and decoder removal after explicit overrides. Ordinary script tests disable host producer detection; real-host inspection is a separate read-only check. Scheduler tests cover UCLAMP/autogroup overrides and the desktop THP policy. These options enable capabilities for a future kernel; performance benefits depend on workload and policies and require measurements after booting that kernel.
